# Step 12 verification: executive briefing

`brief-paper` runs the live graph through `summarize`, then stops before QA readiness. It
combines verified arXiv metadata with Step 11's source-linked evidence. Local Ollama
`qwen2.5:3b` drafts short prose fields. Dense numerical PDF tables use an explicit
qualitative comparison sentence from the caption rather than a model-inferred row/metric
pairing. JSON and Markdown artifacts are saved in `outputs`.

The builder rejects a draft if it cites an unknown or wrong-facet chunk, copies a quote not
present in its cited source, introduces a number absent from that source, omits a documented
limitation, or invents a limitation when the evidence status is `not_found`. It attempts one
corrected draft on validation failure and saves nothing if validation still fails. The JSON
artifact keeps the briefing and a quote audit; Markdown links each claim to the PDF page.
Bibliographic fields are copied directly from metadata rather than generated by Qwen.

The quote/number checks establish traceability, not full semantic entailment. Review the
Markdown beside the cached PDF before sharing it, particularly paraphrases, mathematical
notation, and numerical claims. The LoRA table results are deliberately qualitative because
flattened PDF rows make row-to-metric mapping risky. A user may change the briefing after
source review; QA and durable session reopening remain later steps.

Run from the project virtual environment:

```sh
.venv/bin/python -m arxiv_agent brief-paper 2106.09685v1
```

On a new machine, install dependencies, start Ollama with `qwen2.5:3b`, and run
`doctor --download-models` once. The first uncached paper also needs internet access for
arXiv metadata and its PDF. Existing caches on this machine require no manual setup.
